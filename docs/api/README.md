# Vestail API documentation

Start here.

## Status: not yet reachable

**Neither API surface is exposed on the internet today.** `vestail.fun/v1/*` and
`vestail.fun/api/v1/*` both answer 404, verified against production.

The service is real and running — it answers every request the web app makes — but it
runs *inside* the Next.js process rather than behind a URL. `web/lib/server/local-api.ts`
calls the Hono app directly, with no network hop. Nothing is listening on a public route.

So these pages describe an interface that works, is tested, and cannot yet be called by
anyone outside the server. That is a deployment gap, not a design one, and it is written
here rather than discovered by a partner whose first request returns 404.

## Two surfaces, not one

They are different APIs with different audiences, and conflating them is the easiest
mistake to make in this repo.

| | Internal | Partner |
|---|---|---|
| Mounted at | `/v1` | `/api/v1` |
| Audience | Vestail's own web app | Third parties, under a key |
| Contract | [`openapi.yaml`](./openapi.yaml), hand-written | generated by `services/api/src/public/openapi.js` |
| Shape | `/resolve`, `/matrix`, `/rules`, `/venues`, `/tokens`, `/orders` | `/check`, `/check/batch`, `/assets`, `/countries`, `/rules/{id}` |
| Auth | public read; a key for `POST /orders/click` | a partner key on everything |
| Documented in | [API.md](./API.md) | [partner-api.md](./partner-api.md) |

## A note on how these pages are kept true

Documentation here is checked, not asserted. `scripts/error-codes.test.mjs` reads every
`ApiError` and `errorBody` call in the service and fails if `errors.md` has not listed the
code. That guard exists because the error list had already drifted from four documented
codes to seventeen raised ones, and nothing caught it.

Where a page states a number — a rate limit, a cache age, a batch size — it should be
traceable to a line of source. Where it states something that cannot be checked
automatically, it says so.
