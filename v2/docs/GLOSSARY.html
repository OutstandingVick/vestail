What it is

Vestail answers one question for a person anywhere in the world: can I own this, here, and where do I go to buy it? It turns a typed phrase into an asset class, looks up the ownership rule for every country and buyer type, shows the answer as a grid of coloured tiles, and puts a buy button beside each permitted cell that routes to a partner venue. The routing is the business: every outbound click carries an attribution tag for referral revenue or payment for order flow.

Vocabulary

Asset class
One of the 20 things a person might own (residential property, gold bullion, foreign equities…). Each is a tile. Defined in data/assets.json.
Status
The rule for one (country, asset, buyer type). Three values: can own (2), conditional (1) — licence, cap or approval needed, cannot own (0). Red is hatched so it reads without colour.
Buyer type
Who is buying. Citizen holds the country's passport; foreigner does not. Each country stores a full rule set for both. A resident type is planned.
Row
One country: flag, name, summary count, 20-tile grid, buy column.
Grid / tiles
The 20-box visual. In By status view tiles are sorted green → amber → red and countries are ranked most-open first; in By asset 1–20 view tiles keep their fixed index so you can compare one asset down the column.
Category
A group of asset classes a single word fans out to. "Stocks" → Equities → domestic, foreign, private company shares. data/categories.json.
Alias
An everyday word that maps to an asset class or a category: house, gilts, farmland, crypto. data/aliases.json.
Entity
A specific named thing: Google, Bitcoin, a Gulfstream, UK gilts. Each knows its asset class; listed companies also know their home country. data/entities.json.
Equity-by-home
The rule that a listed company counts as domestic equity in its home country and foreign equity everywhere else. This is why searching "Google" shows a different tile for the US row than for the Nigeria row.
Resolution
The output of the search pipeline: which asset classes a query means, which stage decided it, and a trail of labels explaining the hops.
Trail
The chips under the search bar (Google → Listed company (US) → Equities → Domestic in US, foreign elsewhere). Same data the API returns.
Venue
Where a permitted asset can be bought: a broker, exchange or listings site. Default per asset with per-country overrides. data/venues.json.
Ref tag
The query string appended to every venue link (ref=vestail) so clicks can be attributed. One constant; swap it for partner-specific tags.
Selection
The asset currently chosen for the buy column. Set by clicking a tile or automatically when a search resolves to one asset. Escape clears it.
HUD
The traction strip under the search: volume, orders routed, active buyers, and a live ticker of recent buys. Placeholder numbers until wired to the order log.

Search pipeline

The resolver is the reasoning layer. It does not do substring matching; it runs the query through ordered stages and stops at the first confident hit, recording why.

Stages

0 · Clean
Lower-case, strip punctuation, drop filler words (can, I, buy, a, some, own…).
1 · Entity
Match against the named-entity dictionary with exact › prefix › substring › small-typo scoring. Companies produce a per-country override (equity-by-home).
2 · Alias
Everyday words. If the alias points at a category, all of that category's classes are returned.
3 · Category
A category typed directly.
4 · Asset
An asset class name, prefix and typo tolerant.
Retry
If the whole phrase misses, retry per word — longest first, entities before everything else — so "tesla shares" resolves to Tesla, not the generic "shares" bucket.

Code: packages/core/index.js (portable, no dependencies) and inline in app/index.html section 2. Tests: packages/core/test.js.

Interface

Reading order on the page, top to bottom:

Top bar
Brand mark (a conic gradient of the three status colours) and a one-line scope statement.
Hero
Headline, one-sentence promise, the search field, the HUD, then suggestion chips that fill the search.
Controls
Two segmented toggles (Citizens/Foreigners, By status/By asset) and the legend.
Trail
Resolution chips plus one explanatory line; when nothing is searched it shows a hint about the buy column.
Board
One card per country. Desktop is three columns (identity · grid · buy); below 900px it stacks; below 480px tiles stretch to the full width.
Key
The 20 asset classes in tile order for the By-asset view.
Story sections
Six numbered sections after the key (problem, how it works, verdicts, buy, trust, FAQ) and a closing call to action whose button returns to the search.

Interactions

Type
Re-resolves on every keystroke; clears any manual selection.
Click a tile
Selects that asset for every row; siblings dim; the buy column fills. Click again or press Escape to clear.
Hover / focus a tile
Tooltip with asset name and status. Tiles are buttons, so the keyboard works.
Toggle buyer type
Swaps every row's rule set and re-ranks.

Buy column

For the selected asset in each row the column shows one of four things: Buy on [venue] (blue, green tile), Buy on [venue] in amber behind an acknowledgement checkbox (amber tile; the link stays locked until the buyer ticks it), Not permitted (red tile), or the name of the licensed route when there is no online venue (firearms, trusts, media, telecom, mining). A secondary venue appears as a text link. Venue choice is local override first, default second. Every link opens in a new tab with the ref tag.

With the API connected (window.VESTAIL_API and window.VESTAIL_API_KEY), a click goes to POST /orders/click, which records it and returns the tagged redirect; the page opens the tab during the click and then follows it, so popup blockers allow it. If recording fails the buyer still goes to the venue link, which is already tagged. The API only redirects to a venue listed for that rule, so a cannot-own cell can't be routed. Without the API every link opens directly, as before.

Traction HUD

Three numbers that count up once on load (cubic ease-out, 1.4s, skipped under reduced-motion) and a ticker that advances every 3.2s through recent buys. Numbers live in data-count attributes; the ticker reads a RECENT array. With the API connected both come from GET /activity. Outside production the API still mixes in the sample figures; with NODE_ENV=production it reports recorded clicks only, and volume stays 0 until real order data exists. Fabricated traction is the fastest way to lose trust in a finance product.

Placement rationale: under the search so the eye path is headline → search → proof. Not in the nav (too small to feel real) and not a two-column hero (the board needs full width and the search is the product).

Design system

Brand
Vestail's orange wordmark and character (from v1's public/brand/), inlined in the page and used as the favicon.
Type
Outfit at 300, 400, 600 and 700. The hero headline pairs a Light line with a Bold one; numbers that count use tabular figures.
Colour tokens
Dark only. Background #0D0D0F, surface #17171A, text #F5F4F0, muted #99979F; greys are mixed from the text colour so there is one family. Two accents with fixed jobs: orange #FF580A marks actions and nothing else (Search, See where, Buy); purple #7C5CFF carries brand emphasis (section numbers, change chips, icon tiles, the live dot, selection and focus rings, the hero glow). Verdicts keep their own colours and nothing else uses them: can own #8FBD7F, conditional #D9A84D, cannot own #D98D84 (always hatched).
Cards
One treatment: the surface with a hairline ring and a faint top highlight; raised cards add a soft drop; hover tints the ring purple and lifts the card.
Shape
One corner scale: panels 28px, cards 20px, fields 16px, buttons and small tiles 12px, verdict tiles and swatches 6px, pills for actions, chips and toggles.
Motion
Headline words rise in; tiles pop in with a stagger on first paint only; toggles slide a thumb; trail chips pop; selection scales and dims. Everything honours prefers-reduced-motion.
Why dark only
v1 is deliberately dark-only: its verdict colours hold their meaning and contrast against a dark ground, and a light theme would need a second, separately checked set. v2 follows it.
Responsive
Breakpoints at 900px (stack) and 480px (fluid tiles, full-width buttons, shortened copy). Safe-area insets declared for notched phones.

API

Contract in docs/api/openapi.yaml, guide in docs/api/API.md. Core endpoints: /resolve, /matrix, /rules/{country}/{asset}, /venues/{asset}, /activity, POST /orders/click. The reusable logic behind them is packages/core; the server is services/api (Hono on Node), with its configuration and behaviour notes in services/api/README.md and running instructions in DEPLOY.md.

Open questions

Rule provenance
Every rule now has sources and verified_at, but all are empty: every status is still illustrative until it is checked against a real document. The grid does not show provenance yet.
Partner keys
The page has to carry an API key to record clicks, and anything in a public page can be read. Decide how partner keys and per-partner ref tags work before relying on click attribution.
Click and rate-limit storage
Both live in the API process's memory, so they reset on restart and are not shared between instances. Move them to a store before running more than one.
Securities master
Replace the hand-seeded entity list with ticker/ISIN lookup so any listed company resolves.
Resident buyer type
Many rules differ for residents without citizenship; a third rule set is the obvious next axis.
Affiliate deep links
Venue urls are homepages. Partner agreements will bring specific landing urls and per-partner ref tags.
